<planner_flagged_decisions>
**Correction to D-07's stated mechanism, verified against the installed `viem@2.55.5` source.**

D-07 instructs reading the actual `gas` and `gasPrice`/`maxFeePerGas` "from the failed simulate/write
result (via viem's `InsufficientFundsError`, walked off `BaseError`)". Direct inspection of
`ui/node_modules/viem/errors/node.ts` line 152 shows `InsufficientFundsError`'s constructor takes
only `{ cause }` — it stores **no** gas or fee fields at all. The enclosing errors that *do* receive
them, `EstimateGasExecutionError` (`errors/estimateGas.ts`) and `CallExecutionError`
(`errors/contract.ts`), pass them straight into `prettyPrint` for their `metaMessages` and never
assign them as instance properties either. So the literal instruction is not implementable.

D-07's *intent* — computed, not guessed; a real figure per failure — is honoured with three ordered
sources, and only the third is a constant:

1. **Explicit `gasEstimate` on the input object** (primary, non-fragile). The Phase 3 caller already
   holds these: `useSimulateContract`'s `data.request.gas` and the fee data it uses to submit. This
   is why `DecodeBridgeErrorInput` carries `gasEstimate?: { gas: bigint; feePerGas: bigint }`.
2. **Recovered from the walked cause chain's `metaMessages`** (secondary, degraded). Both enclosing
   errors emit a `prettyPrint` block — `'Estimate Gas Arguments:'` for the estimate path,
   `'Raw Call Arguments:'` for the call path — whose lines are two leading spaces, the key, a colon,
   padding, then the value: `gas` as raw decimal, `maxFeePerGas`/`gasPrice` as a decimal followed by
   the literal `gwei`.
3. **The fixed `0.0004 ETH` default** (tertiary), used only when neither source yields both figures.

`InsufficientFundsError` is still walked — that part of D-07 is correct and unchanged: it is what
*classifies* the failure as a native-gas shortfall. The public shape stays "one string out" per
D-07's own reversibility note.

*Reversibility: `costly` — `DecodeBridgeErrorInput`'s optional `gasEstimate` field is consumed by
Phase 3's orchestration hook; widening or renaming it later touches every call site. Not one-way:
the field is additive and optional, so no migration and no broken contract.*

**No decision in this plan is `one-way`**, so no `checkpoint:decision` is inserted and `autonomous`
stays `true`.
</planner_flagged_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chain node → viem error object → `decodeBridgeError` → user-facing string | Revert data, decoded error args, and Solidity revert-string reasons are all attacker-influenceable bytes. Any address can craft a call that reverts with an arbitrary payload, and that payload reaches user-visible copy. |
| viem error `metaMessages` → gas-figure parse | The secondary gas source parses free text out of an error's own formatted output; that text is derived from RPC-node-supplied values. |

No network calls, no user input parsing beyond revert data, no contract changes, no package installs
in this plan. The register below is scoped to what the plan can actually be exposed to.
