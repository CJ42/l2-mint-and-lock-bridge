<objective>
Retire the phase's one LOW-confidence risk first: prove that a real WSS endpoint for each testnet
actually answers `eth_subscribe` with a notification frame, commit the winners as constants, build
the production WebSocket-first transport on top of them, and prove end-to-end that a live
`BridgeFinalized` subscription genuinely rides `eth_subscribe` rather than silently polling. Then
land the pure merge/threshold logic that every later plan in this phase depends on.

exists and that `webSocket()` sits at `fallback()` index 0. That assumption is the single
LOW-confidence item in the entire milestone's research. Proving or disproving it on the first
commit — rather than after three hooks are already wired — is what keeps a dead endpoint from
becoming a rewrite. D-03 makes either outcome shippable, so this plan cannot fail; it can only
return a different answer.

<decisions_recorded>
Three of this phase's four previously-open gray areas are settled by locked decisions the executor
must not relitigate. This plan implements the transport half of them:

- **D-05 (transport wiring scope):** `webSocket()` goes into **both** the dedicated live-events
  clients (`ui/src/lib/live-clients.ts`) **and** `ui/src/wagmi.ts`'s `transports` map. The hooks are
  built on module-level `createPublicClient` instances, not wagmi's `useWatchContractEvent`, because
  LIVE-01's explicit-`chainId`, wallet-independent requirement is expressed more directly by two
  pinned clients. `wagmi.ts` gains the entry anyway so a future component-local subscription is not
  silently downgraded to polling.
- **D-06 (degrade cadence):** staleness threshold is `max(3 × blockTimeMs, floor)` per chain, and
  the constants chosen here are `blockTimeMs` 2_000 (Base Sepolia) / 400 (Arbitrum Sepolia) with a
  10_000 ms floor. The formula is what is committed and tested, not the resulting number — a future
  block-time regime change re-derives from the formula.
- **D-07 (health visibility):** `TransportMode` is defined here as a four-member string-literal
  union and returned from both hooks (plans 02-03 / 02-04). Nothing in Phase 2 renders it; whether
  `bridge-card.tsx` displays it is Phase 3's decision.
- **D-08 (confirmation mechanism):** relay confirmation is **first-sight of the `BridgeFinalized`
  log plus rollback on a `removed: true` log for the same messageId** — not confirmation-depth
  tracking. `applyLogsByMessageId()` in this plan is that mechanism; the rollback path is required
  under either design, and confirmation-depth can be layered on later without changing it.

**Reversibility of the keyed-provider escalation.** D-01 names a keyed provider (Alchemy / Ankr
free tier) as a backstop if both no-key candidates fail a chain. That path is a genuine one-way
door: a credentialed URL committed to git cannot be un-committed — undoing it means rewriting
history and rotating the key. Rather than gating it with a checkpoint, this plan **removes** the
irreversibility: the autonomous path is forbidden from ever writing a credentialed URL, and a chain
with no passing candidate simply ships HTTP-only per D-03. Escalation remains available as a
separate developer-initiated decision that reopens D-02 for that chain.
</decisions_recorded>

**Detector:** `detected: true` (advisory). The two raw lexical signals are discarded as
coincidental: `"second"` matched the phrase "6-second poll" (a time unit, not a cardinality claim)
and `"fallback"` matched viem's `fallback()` function name (an API identifier, not a plurality
signal). Neither is evidence on its own.

**The real transition, judged on its merits.** There *is* a genuine singular→plural transition in
this phase, but the noun is not "transport" — `ui/src/wagmi.ts` and `use-bridge-messages.ts` already
hold a `fallback([http, http])` array, so transports were already plural. What changes is
**transport health**: today it is an implicit singular assumption ("the client works"), and after
this phase it is an explicit four-member state (`'connected' | 'stale' | 'reconnecting' |
'polling-fallback'`) that every consumer must read rather than assume.

**Noun now primary:** transport health / connection mode.

**Decision:** `promote`.

**Rationale:** after this phase there is no supported code path that assumes connectedness — both
hooks return `transportMode` (D-07) and the watchdog exists precisely because the implicit "it is
fine" state is unsound (viem `wevm/viem#2325`: the socket can sit silently `CLOSED`). Keeping the
implicit state alongside the explicit one would preserve the failure mode the phase exists to
eliminate, so the plural representation replaces rather than joins the singular one.

**Suggested (not required) invariant test:** assert `transportModePriority` has exactly the four
members and that `combineTransportModes` is total over every ordered pair of them — encoding
"there is no implicit fifth 'assumed fine' state". Task 2 includes this as a test case because it
is one assertion and it is the generalized form of the prohibition below.
