<objective>
Give the transaction flow a single-message relay watch: for one `messageId` on one explicitly-named
destination chain, seed from a bounded newest-first scan, subscribe live, and report a status that
can move back to pending if the chain reorganises.

Purpose: this is the hook Phase 3's orchestration layer calls to answer "has the relayer finished?".
Everything about it has to work while the user's wallet is connected to the *origin* chain, which is
why the destination chain id is an argument and never an inference. And because a bridge can finalize
in the seconds between the user closing a tab and reopening it, the seed scan — not the subscription
— is what makes the answer correct on a cold mount.

Output: `ui/src/lib/relay-status.ts` (pure derivation and range arithmetic) with tests, and
`ui/src/hooks/use-relay-status.ts`.
</objective>

<decisions_recorded>
- **D-05:** this hook is built on the module-level `createPublicClient` pattern (via
  `getLiveClient({ chainId })` from plan 02-01), not on wagmi's `useWatchContractEvent`. The reason is
  LIVE-01: a hook that reads wagmi's `Config` from React context inherits whatever chain the wallet is
  on, and this watch must be pinned to the destination chain irrespective of that.
- **D-07:** `transportMode` is part of the returned object, following the existing
  `UseBridgeMessagesResult { messages, isLoading, error, refresh }` shape convention. Nothing here
  renders it.
- **D-08:** confirmation is first-sight plus rollback on `removed: true`, not confirmation-depth
  tracking. The status is *derived* from the messageId-keyed event map on every render rather than
  stored as a flag, which is what makes the rollback path free.
  *Reversibility: reversible — layering confirmation-depth on later means adding a block-number
  comparison inside `deriveRelayStatus`, with no change to the map or to the hook's interface.*
</decisions_recorded>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → destination-chain public RPC endpoint | Every `BridgeFinalized` log this hook acts on arrives from unauthenticated third-party infrastructure. A relay claimed complete here is a claim the user will act on. |
