<objective>
Move the message explorer off its fixed 6-second `getLogs` timer and onto the same live-watch
mechanism the relay watch uses — keeping its bounded seed scan, applying every event exactly once,
rolling back reorged finalizations, and reporting one combined transport mode.

Purpose: the explorer is the part of this UI a user watches while waiting. A 6-second poll is both
the wrong latency and, more importantly, a mechanism that cannot tell the user anything about its
own health — it looks identical whether it is working or silently failing. Replacing it with the
seeded subscription plus watchdog closes LIVE-09 and makes the explorer's freshness a fact the hook
can report rather than a claim printed in a badge.

Output: `ui/src/lib/message-order.ts` with tests, an upgraded `ui/src/hooks/use-bridge-messages.ts`,
and a corrected live badge in `ui/src/components/message-explorer.tsx`.
</objective>
