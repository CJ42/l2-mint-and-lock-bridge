## Contracts consumed (all established elsewhere)

**From Phase 1's `ui/src/lib/derive-flow-state.ts`** — type-only imports; this component imports no
value from that module:

```typescript
export type BridgeStepId     = 'approve' | 'submit' | 'relay'
export type BridgeStepStatus = 'idle' | 'pending' | 'processing' | 'confirmed'
export interface BridgeStep { id: BridgeStepId; status: BridgeStepStatus }
export type BridgeSteps = readonly [BridgeStep, BridgeStep, BridgeStep]
```

Phase 1 guarantees two properties this component depends on and must not re-implement:

1. The relay step never carries the `pending` status — it is never wallet-prompted.
2. In a `failed` flow state, every step whose status would have been `pending` or `processing` is
   already returned as `idle`; steps already `confirmed` stay `confirmed`. So the failure rendering
   this plan's `must_haves` describes needs **zero** failure-specific branching here — rendering
   `idle` as upcoming is what produces it.

**From Phase 2's `ui/src/lib/live-transport.ts`** — type-only import:

```typescript
export type TransportMode = 'connected' | 'stale' | 'reconnecting' | 'polling-fallback'
```

export interface SpinnerProps { mode: 'on-white' | 'on-blue' }

**From plan 03-01's `ui/src/hooks/use-bridge-flow.ts`** — the two fields this plan reads off the hook
result in `page.tsx`: `flowState.steps` and `transportMode`. Confirm both against
